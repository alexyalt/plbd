# Техническое задание: локальная веб-система учёта защиты зелёных насаждений

Версия 0.1 (черновик для согласования). Дата: 2026-11-26.
Основание: `docs/ANALYSIS.md` (анализ существующих баз Access и VBA-кода).

## 1. Цель

Заменить связку из двух Access-баз (`BD_table.accdb` — данные, `BD_forms_1 (1).accdb` — формы, отчёты, VBA) локальным веб-приложением, которое:

- работает в браузере на одном компьютере (без сервера, без Access и без Windows-специфичных драйверов);
- сохраняет все накопленные данные и расчёты;
- запускается одной командой `python run.py`.

## 2. Границы

В объёме:
- перенос данных из `BD_table.accdb` в SQLite;
- CRUD-интерфейс по всем сущностям;
- сценарии, которые сегодня реализованы формами и VBA (раздел 5);
- формирование документов (раздел 6);
- импорт из `.accdb` и экспорт резервной копии.

Вне объёма (первая версия):
- многопользовательская работа по сети, роли и авторизация (приложение слушает только `127.0.0.1`);
- мобильное приложение;
- перенос файлов документов и фото: папки `Template`, `Report_Photo`, `Report_Damage` в репозитории отсутствуют.

## 3. Технологии

| Слой | Решение | Обоснование |
|---|---|---|
| Язык / фреймворк | Python 3.11+, Django | Админка и формы дают CRUD с минимумом кода |
| БД | SQLite, один файл `data/plbd.sqlite3` | Локальное использование, простое копирование |
| Интерфейс | Django templates + HTMX (без сборки frontend) | Нет Node.js, меньше зависимостей |
| Документы | `openpyxl` по шаблонам `.xltx` | Печатные формы уже существуют в Excel |
| Импорт `.accdb` | `pyodbc` + драйвер ACE (Windows); запасной путь — CSV | Чистый Python `access-parser` падает на файлах Access 2010+ (KeyError 4096) |

## 4. Модель данных

Целевая схема нормализована; старые ключи сохраняются в поле `legacy_id`, чтобы можно было сверить результат миграции.

Исходные данные (число строк подтверждено полным экспортом):

| Таблица Access | Строк | Целевая сущность |
|---|---|---|
| `location` | 35 | `Location` (объект), поле `code` из `loc_code` |
| `place` | 312 | `Place` (куртина), FK на `Location` вместо текстового `parent` |
| `flora` | 348 | `Plant` (название, латинское название) |
| `pest` / `sickness` / `physiology` / `other` | 91 / 76 / 26 / 21 | `Cause` с типом (вредитель, болезнь, физиология, другое) |
| `farma` | 191 | `Preparation` + новое поле «действующее вещество» |
| `person` | 28 | `Person` (ФИО и должность сохраняются как есть) |
| `inspection` | 7 304 | `Inspection` |
| `treat` | 10 291 | `Treatment` + `TreatmentReagent` (строки вместо `reag1..4`, `reag_count1..4`) |
| `task` | 41 | `TaskType` |
| `protection` | 7 | `ProtectionRule` (график профилактики) |
| `docs` | 6 | `DocumentTemplate` |

Ключевые решения:
- `reag1..reag4` и `reag_count1..4` превращаются в связанную таблицу `TreatmentReagent(treatment, preparation, quantity)`.
- Текстовые ссылки (`inspection.flora`, `inspection.location`, `treat.person`, `treat.location`) заменяются внешними ключами. Несопоставленные значения не отбрасываются: они попадают в отчёт миграции (раздел 7).
- Состав растений в `place.content` (текст через `;`) разбирается в связь `Place` — `Plant`; исходный текст сохраняется в `content_raw`.
- `Inspection.id` в Access похож на дату с номером (максимум 2026111925). Он хранится в `legacy_id`, а новый ключ — суррогатный.

## 5. Функциональные требования

Обозначения приоритета: M — обязательно, S — желательно.

| № | Требование | Прио |
|---|---|---|
| F1 | CRUD для всех справочников из раздела 4 с поиском и сортировкой | M |
| F2 | Ввод акта осмотра: дата, объект, куртина, растение, количество, описание, причина (из четырёх справочников), назначенные меры, автор, признак «в работе» и «выполнено», ссылка на предыдущий осмотр | M |
| F3 | Ввод обработки: дата, объект, растение, садовник, объём бака, препараты и их дозы, расход бензина, результат, тип обработки, признак списания; связь с осмотром | M |
| F4 | Автоматический расчёт расхода препарата по формуле legacy: `доза на 10 л × объём бака / 10` | M |
| F5 | Отметка «списано» и формирование отчёта о расходовании ТМЦ за период по объекту | M |
| F6 | График защиты (`protection`): по фенофазе показать, какие вредители и какие препараты актуальны | S |
| F7 | Поиск дублей справочника препаратов (12 повторяющихся названий) и их слияние с переносом ссылок | M |
| F8 | Фильтры списков по периоду, объекту, растению, статусу | M |
| F9 | Журнал изменений (кто и когда менял запись) | S |

Точные правила расчёта и поведение каждой формы должны быть сверены с `docs/legacy/vba_source.txt` при реализации; расхождения фиксируются в `workbook.md`.

## 6. Документы и отчёты

Печатные формы формируются в `.xlsx` по существующим шаблонам:

| Шаблон | Документ |
|---|---|
| `insp_report (1).xltx` | Акт обследования |
| `spravka_inObjekt (1).xltx` | Справка «Список проблем на подконтрольном участке» |
| `treet_report (1).xltx` | Справка по обработкам |
| `work_book (1).xltx` | Рабочая книга (журнал обработок) |
| `farma_report.xltx`, `farma_report.xltm` | Справка по обработкам, отчёт о расходовании ТМЦ |
| `doc_report.xltx` | Форма СУ-21 «Выдача под отчёт» |

Макрос из `farma_report.xltm` не переносится: его логику реализует код приложения. Подписи (научный сотрудник, замначальника СПС, агроном) выносятся в настройки.

## 7. Миграция данных

1. Команда `python run.py import-access <путь>` читает `.accdb` и создаёт новую БД.
2. Исходные файлы никогда не изменяются.
3. После импорта формируется `data/migration_report.md`: число строк по таблицам (исходное и новое), несопоставленные текстовые ссылки, дубли препаратов, пустые даты (в `inspection` найдена 1 запись без даты).
4. Приёмка миграции: количества строк совпадают, а суммарный расход по каждому препарату за выбранный год совпадает с расчётом в Access.

Известные проблемы данных описаны в `docs/ANALYSIS.md`, раздел 5.

## 8. Нефункциональные требования

- Запуск: одна команда `python run.py` создаёт окружение при необходимости, применяет миграции, запускает сервер и открывает браузер.
- Приложение слушает только `127.0.0.1`.
- Интерфейс на русском языке; даты в формате ДД.ММ.ГГГГ.
- Резервная копия: кнопка «Сохранить копию» складывает файл БД в `backups/` с датой.
- Работа на Windows 10+ без прав администратора, если установлен Python.
- Размер БД порядка десятков мегабайт; списки по 10 000+ строк открываются с пагинацией не дольше секунды.

## 9. Персональные данные и репозиторий

Таблица `person` содержит фамилии и должности. По решению заказчика они остаются в данных. Репозиторий `alexyalt/plbd` публичный, а в нём лежат `.accdb` с этими данными, поэтому:

- токены доступа в репозиторий и в `workbook.md` не записываются;
- ранее раскрытый токен считается скомпрометированным и должен быть отозван;
- после миграции файл БД `data/` и резервные копии в Git не попадают (`.gitignore`).

## 12. Критерии приёмки

- Все таблицы из раздела 4 перенесены, `migration_report.md` не содержит необъяснённых расхождений.

- `python run.py` на чистой машине с Python запускает систему.
